# Справочник настроек Shadowrocket

Собрано 13 ноября 2026 из открытых описаний. У приложения нет опубликованного полного официального мануала. Основной текст — неофициальный справочник [LOWERTOP/Shadowrocket](https://github.com/LOWERTOP/Shadowrocket) (страница [lowertop.github.io/Shadowrocket](https://lowertop.github.io/Shadowrocket/)): его ведут по списку ключевых слов [официальной группы](https://t.me/ShadowrocketApp) и по журналу обновлений, вместе с формальной и тестовой сборкой. Второй слой — комментарии в [lazy_group.conf](https://raw.githubusercontent.com/LOWERTOP/Shadowrocket/main/lazy_group.conf) той же группы, дата в шапке файла 15 октября 2026. Отдельные ключи, которых в этом списке нет, взяты из экспорта самого приложения и из публичных конфигов; у каждой такой строки стоит пометка.

Поведение зависит от версии. Справочник группы прямо пишет, что скрытые ключи перечислены не все, и отсылает к `buginapp@gmail.com`. Разработчик — [Shadow Launch Technology Limited](https://shadowlaunch.com), приложение в App Store: [Shadowrocket](https://apps.apple.com/us/app/shadowrocket/id932747118), iPhone, iPad, Mac, Apple TV. Репозиторий LOWERTOP с разработчиком не связан.

Локальные рабочие примеры этого репозитория — `sr.conf` и `sr_cor.conf`. Они не спецификация.

## Где что настраивается

| Место | Что там |
| --- | --- |
| Файл `*.conf`, раздел `[General]` | DNS, TUN, IPv6, совместимость |
| Тот же файл, остальные разделы | Правила, группы, Hosts, переписывание, MITM, скрипты |
| Конфигурация → модули | Тот же формат, что у конфига; правила модуля стоят выше правил файла |
| Настройки приложения | Подключение по требованию, туннель, тип прокси, UDP, STUN, Tailscale, GeoIP, автообновление |
| Узел и подписка | Протокол, UDP-пересылка, цепочка, фильтр подписки |

Встроенный `default.conf` содержит набор правил и обновляется вместе с приложением. Сброс: Конфигурация → восстановить конфигурацию по умолчанию.

Файл добавляют по URL (Конфигурация → «+») или из облака. Принимается и Clash YAML: стандартная ссылка Clash с узлами заводит и конфиг, и узлы. Удалённый файл можно смотреть (предпросмотр), перезаписать с сервера (обновление) и переименовать. «Использовать» и «скомпилировать» заново скачивают правила и скрипты по URL и переводят файл во внутренний формат текущей версии. Обновление затирает местные правки.

Правка через интерфейс не показывает скрытые ключи `[General]`. Их пишут в чистом тексте: `ключ = значение`.

## Разделы файла

`[General]`, `[Proxy]`, `[Proxy Group]`, `[Rule]`, `[Host]`, `[URL Rewrite]`, `[Header Rewrite]`, `[Body Rewrite]`, `[Map Local]`, `[MITM]`, `[Script]`.

Комментарий — строка с `#`. Несколько значений в одном ключе разделяют запятой.

Включение другого файла:

```
include = другой.conf
```

Текущий файл важнее включённого. То же действие в интерфейсе: общий раздел → включить конфигурацию, либо «расширить конфигурацию» из меню файла.

## Глобальный маршрут

Режим на главном экране режет движок правил.

| Режим | Поведение |
| --- | --- |
| Конфигурация | Идёт по правилам активного файла и модулей |
| Прокси | Весь трафик в один узел. Группы при этом не работают |
| Прямое соединение | Весь трафик мимо узлов |
| Сценарий | По типу сети выбирает заранее заданные режим, файл и узел |

Сценарий задаётся для Wi-Fi (с именем сети), сотовой сети и значения по умолчанию. Имя Wi-Fi читается только с разрешением геолокации; без него галочка в списке сценариев не переключается сама, сценарий при этом применяется. Для нескольких сотовых интерфейсов в поле пишут `pdp_ip1`, `pdp_ip2` и дальше; пустое поле — `pdp_ip0`. Интерфейсы видны в Настройки → диагностика → сеть. Пункты туннеля «включать все сети» могут помешать сценарию. Сценарии и группы на главном экране в iCloud не уходят, их сохраняют вручную.

Простой режим (главный экран → глобальный маршрут → группа) сам выбирает узел с меньшей задержкой и подставляет его в политику `PROXY`. Справочник считает его устаревшим: то же делает группа типа `url-test`. Период и допуск берутся из Настройки → метод проверки задержки → URL, по умолчанию 600 с и 0 мс.

«Включить откат» после трёх неудач соединения переключает узел среди доступных, без учёта задержки и порядка в списке. Для политики `PROXY` круг — все узлы на главном экране, либо узлы группы, если включён простой режим. Для группы не типа `select` круг — её узлы. Куда переключилось, видно в журнале прокси.

## `[General]`: ключи с экраном

Экран: файл → ⓘ → Общие. `bypass-system` с экрана убран, ключ в старых файлах ещё встречается.

| Ключ | Что делает |
| --- | --- |
| `skip-proxy` | Имена и адреса из списка обрабатывает интерфейс TUN, а не прокси-интерфейс приложения. Это не прямое соединение. В режиме «тип прокси = None» туннель и так забирает все соединения, список можно не заполнять |
| `tun-excluded-routes` | Диапазоны, которые не входят в TUN. Интерфейс TUN обрабатывает TCP; обход нужен, чтобы остальные протоколы шли своим путём |
| `tun-included-routes` | Дополнительные, более узкие маршруты. Иначе маршрут Wi-Fi бывает специфичнее маршрута по умолчанию, и часть пакетов в туннель не попадает |
| `dns-server` | Подмена DNS. Параллельный опрос, берётся первый ответ. Имена с политикой прокси резолвит сервер узла; этот ключ обслуживает прямые имена. `system` — системный резолвер |
| `direct-dns-server` | Резолвер только для доменных правил с прямым соединением. Пусто — работает `dns-server`. Ошибка разбора — запасной DNS. Прямое соединение, которое выбрала IP-правило, идёт по `dns-server` |
| `fallback-dns-server` | Запас, если основной запрос не удался или длится дольше 2 с. Пусто и слово `system` — системный резолвер. В журнале DNS ответ дольше 2 с означает, что сработал запас |
| `ipv6` | `true` — запрашивать A и AAAA. `false` не мешает взять IPv6-адрес самого узла, если сеть и имя узла его отдают. Чтобы узел не уходил в IPv6, отключают AAAA у его имени или прописывают адрес в `[Host]` |
| `prefer-ipv6` | `true` — сначала спрашивать AAAA у IPv6-резолвера и предпочитать IPv6. `false` — выключено; при `ipv6 = true` предпочтение остаётся за IPv4 |
| `private-ip-answer` | `false` — частный адрес в ответе считается подменой, и соединение уходит в прокси |
| `always-real-ip` | Пока TUN отвечает на DNS, отдавать настоящий адрес, а не подставной. В ленивом конфиге строка пустая. В публичных файлах встречаются шаблоны (`time.*.com`) и `*` |
| `hijack-dns` | Перехват DNS, зашитого в программу. Пример из ленивого конфига: `8.8.8.8:53,8.8.4.4:53`. Форму `:53` справочник группы не описывает; в `sr.conf` этого репозитория она стоит как перехват любого запроса на порт 53 |
| `include` | Вложить другой конфиг. Текущий файл важнее |
| `bypass-system` | Снят с интерфейса, в справочнике помечен как оставленный. Выключение в старых версиях задерживало push |

## `[General]`: скрытые ключи

Их нет на экране «Общие». Справочник группы просит ставить их осторожно и пишет, что список может быть неполным.

| Ключ | Значения | Что делает |
| --- | --- | --- |
| `dns-direct-system` | `true` / `false` | Доменные правила прямого соединения резолвятся системным DNS |
| `dns-direct-fallback-proxy` | `true` / `false` | Если прямое имя не разобралось, идти через прокси |
| `icmp-auto-reply` | `true` / `false` | Самому отвечать на ping |
| `always-reject-url-rewrite` | `true` / `false` | `false` — отказ в URL-переписывании работает в режиме конфигурации. `true` — и в остальных глобальных режимах |
| `udp-policy-not-supported-behaviour` | `DIRECT`, `REJECT` | Куда деть UDP, если политика правила не умеет его везти. `DIRECT` — напрямую, `REJECT` — отбросить |
| `stun-response-ip` | адрес | Подставной IPv4 в ответе STUN, чтобы не светить внешний адрес. Включённый здесь ключ отменяет тумблер «запретить STUN» в настройках |
| `stun-response-ipv6` | адрес | То же для IPv6, пример из ленивого конфига: `::1` |
| `compatibility-mode` | `0`…`5` | Важнее одноимённого пункта в настройках. `0` — авто или выключено. `1` — прокси с loopback. `2` — только прокси. `3` — только TUN, то же, что тип прокси None. `4` — прокси без loopback. `5` — без маршрута по умолчанию, то же, что режим совместимости в настройках. Остальные числа справочник не гарантирует |
| `always-ip-address` | `true` / `false` | Все имена резолвить местным DNS. Справочник предупреждает: у CDN от этого ломается выбор площадки |
| `proxy-dns-server` | как у `dns-server` | Резолвер имён узлов. Пусто — имена узлов идут через `dns-server`. Для DNS через прокси имя резолвера без этого ключа берётся из системного DNS |
| `close-if-proxy-chain-missing` | `true` / `false` | `true` — нет промежуточного узла цепочки, соединение отклоняется. `false` или пусто — промежуточный узел пропускают и подключаются к конечному |
| `ipv6-only-if-no-ipv4-dns` | `true` / `false` | Сеть считается IPv6-only, если системе выдали только IPv6-DNS |
| `block-quic` | `all-proxy`, `all`, `always-allow` | QUIC, то есть UDP/443. `all-proxy` режет его у соединений через прокси, прямые не трогает. `all` режет UDP/443 у всех. `always-allow` ничего не режет. Тот же эффект даёт правило `AND,((PROTOCOL,UDP),(DST-PORT,443)),REJECT-NO-DROP` |
| `use-local-host-item-for-proxy` | `true` / `false` | По умолчанию прокси-имена резолвятся на дальнем сервере. `true` — если в `[Host]` есть запись, в прокси уходит уже подставленный адрес |
| `allow-dns-svcb` | `true` / `false` | `false` по умолчанию: запросы SVCB и HTTPS глушатся, чтобы система спросила A и получила подставной адрес. `true` эти запросы разрешает |
| `allow-dns-all` | `true` / `false` | По умолчанию включено. `true` — на A и AAAA подставной адрес, остальные типы уходят вверх. `false` — всё, кроме A и AAAA, отвечает пустым |

### Ключи вне списка группы

Их нет в разделе скрытых ключей справочника. Они встречаются в файлах, которые пишет само приложение, и в публичных шаблонах.

| Ключ | Откуда | Что про него известно |
| --- | --- | --- |
| `update-url` | Раздел автообновления того же справочника | Адрес, с которого «обновить конфигурацию» забирает файл. Если адрес есть, автообновление затирает местные правки. Строку удаляют или комментируют, когда нужно обновлять только наборы правил и скрипты |
| `dns-fallback-system` | Экспорт приложения, пример на Habr от 20 ноября 2023 со строкой `# Shadowrocket:` и ключом `dns-fallback-system = false`. Клиент Chute в [своём описании DNS](https://manual.chute.life/en/dns/dns-server.html) читает чужой профиль так: `true` дописывает `system` в пул `fallback-dns-server` и сливает оба ключа, если заданы вместе. `dns-direct-system = true` он же читает как `direct-dns-server = system` | В `sr.conf` этого репозитория `false` сопровождается комментарием «не падать на системный DNS» |
| `bypass-tun` | Старые публичные шаблоны, в том числе разборы конфигов misha-tgshv | В тексте 2026 года группа этот ключ не описывает. Ту же задачу — вывести диапазоны из TUN — справочник отдаёт ключу `tun-excluded-routes`. Совпадение имён не проверено |

## Запись DNS

Один ключ — один список через запятую.

| Запись | Протокол |
| --- | --- |
| `1.2.3.4` или `1.2.3.4:53` | Обычный DNS |
| `system` | Резолвер системы |
| `https://dns.example/dns-query` | DNS-over-HTTPS. Если сервер умеет HTTP/3, клиент пробует перейти на него. Суффикс `#no-h3` этот переход запрещает |
| `h3://dns.example/dns-query` | DoH сразу по HTTP/3 |
| `tls://1.2.3.4` или `tls://имя:853` | DNS-over-TLS |
| `quic://1.2.3.4` | DNS-over-QUIC |

Суффиксы после `#`, несколько штук через `&`:

| Суффикс | Смысл |
| --- | --- |
| `#proxy` и `#proxy=proxy` | Запрос DNS уходит через узел по умолчанию |
| `#proxy=` + имя в URL-кодировании | Через названный узел. Кривое имя тихо заменяется узлом по умолчанию |
| `#ecs=120.76.0.0/14\|2620:149:af0::10/56` | EDNS Client Subnet: серверу сообщают эту подсеть, а не адрес клиента |
| `ecs-override=true` | Подсеть из `ecs` важнее того, что сервер видит сам |

Имя DoH-сервера при `#proxy` без `proxy-dns-server` резолвится системным DNS.

## `[Rule]`

Строка: `ТИП,значение,политика` и необязательные флаги через запятую. Совпадение идёт сверху вниз и останавливается на первой подошедшей строке. Правила модуля выше правил файла. Доменные правила выше IP-правил. При компиляции явные правила остаются впереди, вывод по базе (GeoIP) уходит за них, `FINAL` всегда последний.

Одинаковое значение, записанное сразу в несколько близких доменных типов (`DOMAIN`, `DOMAIN-SUFFIX`, `DOMAIN-KEYWORD` и соседние), срабатывает только в одном из них.

### Типы

| Тип | Совпадение |
| --- | --- |
| `DOMAIN` | Имя целиком |
| `DOMAIN-SUFFIX` | Суффикс: `example.com` ловит `a.example.com` и глубже |
| `DOMAIN-KEYWORD` | Подстрока имени |
| `DOMAIN-WILDCARD` | Шаблоны `*` и `?` |
| `USER-AGENT` | Строка User-Agent, `*` разрешена |
| `URL-REGEX` | Регулярное выражение всего URL |
| `IP-CIDR` | Диапазон IPv4 или IPv6. Отдельного типа `IP-CIDR6` в списке нет |
| `IP-ASN` | Номер автономной системы |
| `GEOIP` | Страна по базе GeoIP, код как `CN` |
| `DST-PORT` | Порт назначения |
| `RULE-SET` | Внешний файл. Внутри строки с типом. Файл из одних IP без типа тоже принимается. Окончание имени файла роли не играет, смотрят содержимое |
| `DOMAIN-SET` | Внешний файл из имён, без типа правила |
| `SCRIPT` | Имя скрипта типа `rule` |
| `AND` | Все вложенные условия. Пример: `AND,((DOMAIN,www.example.com),(DST-PORT,123)),DIRECT` |
| `OR` | Любое вложенное условие |
| `NOT` | Отрицание вложенного условия |
| `PROTOCOL` | Транспорт. Сам по себе не ставится, только внутри `AND`, `OR`, `NOT`. В справочнике группы разобран пример `UDP` |
| `FINAL` | Всё, что не совпало выше |

`PROTOCOL` в примере группы: `AND,((PROTOCOL,UDP),(DST-PORT,443)),REJECT-NO-DROP`.

### Политики

`PROXY` — узел у переключателя на главном экране. `DIRECT` — мимо узлов. `TAILSCALE` — в туннель Tailscale, модуль в настройках должен быть включён.

Отказ:

| Политика | Ответ |
| --- | --- |
| `REJECT` | HTTP 404, пустое тело |
| `REJECT-DICT` | HTTP 200, пустой JSON-объект |
| `REJECT-ARRAY` | HTTP 200, пустой JSON-массив |
| `REJECT-200` | HTTP 200, пустое тело |
| `REJECT-IMG`, `REJECT-TINYGIF` | HTTP 200, GIF 1×1 |
| `REJECT-VIDEO` | HTTP 200, пустой MP4 |
| `REJECT-DROP` | Пакет отбрасывается |
| `REJECT-NO-DROP` | ICMP «порт недоступен» |

Политикой может быть имя группы, подписки или конкретного узла.

На iOS отдельного «прокси для приложения» нет. Приложение обходят набором доменов, IP и User-Agent. Готовые наборы для Shadowrocket публикует [blackmatrix7/ios_rule_script](https://github.com/blackmatrix7/ios_rule_script/tree/master/rule/Shadowrocket): каталог `rule/Shadowrocket/.../*.list` подключают как `RULE-SET`, файл одних имён — как `DOMAIN-SET`.

### Флаги строки

| Флаг | Где | Что делает |
| --- | --- | --- |
| `no-resolve` | IP-правила | Запрос с именем это правило пропускает и местный DNS из-за него не спрашивает. Без флага перед IP-правилом имя резолвится местным DNS, и сравнение идёт по адресу |
| `extended-matching` | Доменные правила | Сверять и SNI, и заголовок Host. В справочнике сказано, что сверка SNI и так включена |
| `pre-matching` | Правила с отказом | Проверка до обычного прохода, выше остальных правил |

Пример: `DOMAIN,ad.example,REJECT,extended-matching,pre-matching`.

Набор обновляют вручную пунктами «использовать» и «скомпилировать» или фоновым автообновлением. Просмотр набора: в списке правил смахнуть строку влево. Проверка, какое правило возьмёт запрос: Конфигурация → проверить правила.

## `[Proxy]` и узлы

Узлы в файле нужны для совместимости с чужими конфигами. Обычный путь — подписка, ссылка или форма на главном экране. Повтор той же подписки: дописать к URL `#1`, `#2`. Скрытая подписка (длинное нажатие или максимум `0`) не показывает узлы.

Протоколы, которые справочник перечисляет для формальной и тестовой сборок. Актуальный набор — в меню «+» на главном экране.

Subscribe, Shadowsocks, ShadowsocksR, Vmess, VLESS, Relay, Socks5, Socks5 Over TLS, HTTP, HTTPS, HTTP2, HTTP3, Trojan, Hysteria, Hysteria2, AnyTLS, Sudoku, TUIC, Juicity, SSH, WireGuard, OpenConnect, TrustTunnel, MASQUE, Snell, Mieru, Brook, Lua.

Строка в `[Proxy]`: `имя = протокол,адрес,порт,...`. Дальше пары `ключ=значение`.

| Протокол | Обязательное и типичные пары |
| --- | --- |
| `ss` | `password`, дальше `method`, `obfs`, `plugin` |
| `vmess` | `password`, дальше `alterId`, `method`, `obfs`, `tfo` |
| `vless` | `password`, `tls=true`, дальше `obfs`, `peer` |
| `http`, `https`, `socks5` | адрес, порт, пользователь, пароль без имён полей |
| `socks5-tls` | то же и `skip-common-name-verify=true` |
| `trojan` | `password`, дальше `allowInsecure`, `peer` |
| `hysteria` | `auth`, `obfsParam`, `protocol`, `udp=1`, дальше `peer`, `alpn`, `upmbps`, `downmbps` |
| `hysteria2` | `auth`, `obfsParam`, `udp=1`, дальше `peer`, `alpn` |
| `tuic`, `juicity` | `password`, `udp=1`, дальше `user`, `peer`, `alpn` |
| `wireguard` | `privateKey`, `publicKey`, `ip`, `udp=1`, дальше `dns`, `mtu`, `keepalive`, `reserved` через `/` |
| `snell` | `password`, `udp=1`, дальше `obfs`, `obfs-host`, `obfs-uri` |

WireGuard ещё вставляется из буфера в формате `[Interface]` / `[Peer]`: `PrivateKey`, `Address`, `DNS`, `MTU`, `PublicKey`, `AllowedIPs`, `Endpoint`, `Reserved`.

Цепочка: у узла A в поле «прокси через» выбирают B, путь `клиент → B → A → сайт`. Промежуточным может быть группа. Сброс — «отмена» в том же поле. Не каждый протокол годится конечным узлом цепочки.

Знак `⚠` у узла: TLS, в адресе IP, SNI не задан. Приложение само включает «разрешить небезопасное» и пропускает проверку сертификата.

Флаг у узла берётся из начала заметки. Не вышло — страна адреса по базе. Emoji флага в начале заметки при сохранении становится флажком и из текста пропадает. Адрес узла можно пометить флагом вручную.

Фильтр подписки (ⓘ подписки → фильтр), регулярное выражение. В группах те же выражения, без окаймляющих `/`.

| Задача | Выражение |
| --- | --- |
| В имени есть A и B | `/(?=.*(A))^(?=.*(B))^.*$/` |
| Есть A или B | `A\|B` |
| Нет ни A, ни B | `/^((?!(A\|B)).)*$/` |
| Есть A и нет B | `/(?=.*(A))^((?!(B)).)*$/` |

Тот же фильтр принимает скрипт правки узлов: `$server.title`, `$server.reserved`, `$server.mux`, `$server.chain`, `$server['dialer-proxy']`, `$server.host`. Примеры лежат в справочнике и в репозитории [Shadowrocket-First](https://github.com/LOWERTOP/Shadowrocket-First).

Проверка задержки на главном экране: TCP (время установки TCP), ICMP, CONNECT (HTTP HEAD на проверочный URL; справочник советует его). Длинное нажатие на кнопку проверки меняет метод на один раз. URL и период: Настройки → метод проверки задержки, либо кружок рядом с кнопкой проверки. У группы свой URL внизу карточки группы.

UDP-пересылка включается в трёх местах: Настройки → UDP, ⓘ подписки, ⓘ узла. Справочник не описывает режимы упаковки UDP внутри конкретного протокола.

Обновление подписки: смахнуть строку, кнопка на главном экране, «при открытии», фон от 1 до 24 часов (нужен фоновый режим iOS), команда быстрого доступа, долгое нажатие на значок, схема `shadowrocket://update-subs`. Ошибки, как их называет справочник: `forbidden` — токен, `not found` — путь, `service unavailable` — имя или блокировка, ошибка SSL — нет безопасного соединения. Обход: обновить подписку в режиме «прокси» через другой узел или сменить сеть.

Счётчик на подписке приходит заголовком `subscription-userinfo: upload=...; download=...; total=...; expire=...` либо полями `STATUS=` / `REMARKS=` перед base64 тела.

## `[Proxy Group]`

Строка:

```
имя = тип, политика, политика, interval=600, timeout=5, tolerance=100, url=http://www.gstatic.com/generate_204, policy-regex-filter=HK|香港, policy-select-name=узел, select=0, hidden=0
```

Подписка внутри группы: имя подписки, `use=true`, при необходимости тот же `policy-regex-filter`. Несколько подписок через запятую.

| Тип | Выбор узла |
| --- | --- |
| `select` | Вручную. Справочник разрешает вкладывать сюда другие группы |
| `url-test` | Наименьшая задержка по последней проверке |
| `fallback` | Следующий живой узел из прошлой проверки, когда текущий недоступен |
| `load-balance` | Разные правила по разным узлам; одно имя остаётся на одном узле |
| `random` | Случайный узел на запрос, одно имя может уйти на разные узлы |

Кроме `select`, тип живёт проверками. Между проверками мёртвый узел может ещё использоваться. Вложенные группы в такие типы справочник не советует: ручной выбор на экране проверку в фоне не отменяет.

| Параметр | Смысл |
| --- | --- |
| `interval` | Секунды между проверками |
| `timeout` | Секунды, после которых проверка бросается |
| `tolerance` | Смена лидера, только если новый лучше старого больше чем на это значение |
| `url` | Адрес проверки |
| `policy-select-name` | Какой вложенный пункт выбран у ручной группы |
| `select` | Номер вложенного пункта у автогруппы: `0` первый, `1` второй |
| `policy-regex-filter` | Какие узлы попадают в группу |
| `hidden` | `1` прячет группу с экрана, с версии 2.2.66 (2649). Только текст, экрана у параметра нет |
| `use` | `true` — брать узлы названных подписок |

С версии 2.2.65 (2604) у групп есть «проверить и выбрать самый быстрый», с 2.2.91 (3405) — сортировка по ping. Оба тумблера общие для всех групп. К списку групп: потянуть главный экран вниз или значок над местными узлами (с 2.2.65, сборка 2614).

Замена политики по всему файлу: редактирование → заменить политику.

## `[Host]`

| Запись | Смысл |
| --- | --- |
| `имя = 1.2.3.4` | Не спрашивать DNS, взять этот адрес |
| `имя = server:1.2.3.4` | Это имя спрашивать у этого DNS. Несколько адресов через запятую |
| `имя = server:system` | Спросить у системного резолвера. В ленивом конфиге так сделаны `*.apple.com` и `*.icloud.com` |
| `ssid:имя-сети = server:1.2.3.4` | DNS только в названной сети Wi-Fi |

Для прокси-имён запись действует на само соединение, если `use-local-host-item-for-proxy = true`. Иначе дальняя сторона резолвит исходное имя.

## Переписывание

### `[URL Rewrite]`

Строка из регулярного выражения, замены и кода. Коды из справочника: `302`, `307`, `HEADER` и политики, включая отказ.

```
^https?://(www\.)?g\.cn https://www.google.com 302
^http://ads\.example - reject
```

### `[Header Rewrite]`

Куда: `http-request` или `http-response`. Действие: `header-del`, `header-add`, `header-replace`, `header-replace-regex`. Плюс регулярное выражение URL и поле заголовка. Готового шаблона строки справочник не даёт, поля те же на экране.

### `[Body Rewrite]`

`http-request` и `http-response` для тела, `http-request-jq` и `http-response-jq` для фильтра `jq`. Плюс регулярное выражение URL.

### `[Map Local]`

Ответ из самого приложения, без выхода в сеть.

| Тип | Тело ответа |
| --- | --- |
| `text` | Текст из поля данных |
| `file` | Файл, в том числе по удалённому адресу |
| `tiny-gif` | GIF 1×1 |
| `base64` | Данные в base64 |

Дополнительно можно отдать свои заголовки.

## `[MITM]`

Расшифровка HTTPS только у того файла, где она включена. Сертификат: файл → ⓘ → HTTPS-расшифровка → сертификат → создать CA → установить профиль → доверять ему в настройках системы. Пароль личности сертификата по умолчанию `Shadowrocket`. На нескольких устройствах с одним файлом в iCloud сертификат копируют кнопкой у уже установленного, новый CA не создают. Ошибка `No PKCS12 Certificates` бывает, если модуль с сертификатом включили раньше, чем сертификат установлен и доверен.

С версии 2.2.81 (сборки 3096–3099) расшифровка умеет HTTP/2: тумблер на том же экране или `h2 = true`. Модуль с этой строкой перекрывает файл.

`hostname` — кого расшифровывать, шаблоны разрешены. Минус в начале исключает имя: `-*.example.com`. Имена вроде `*.apple.com` и `*.icloud.com` справочник не советует: система и часть программ доверяют только своим сертификатам.

В модуле, чтобы дописать имена, а не заменить список файла:

```
[MITM]
hostname = %APPEND% *.example.com
```

Сертификат модулем, чтобы смена файла не требовала новой установки:

```
[MITM]
enable = true
ca-passphrase = пароль
ca-p12 = содержимое
```

Содержимое берётся копированием у уже установленного сертификата. `ca-passphrase` нужен, когда вложенный файл уже задал другой пароль.

Параметры модуля не затираются его обновлением. Объявление:

```
#!name=имя
#!desc=описание
#!arguments=сертификат:false, пароль:Shadowrocket
#!arguments-desc=пояснение к полям
```

В тексте модуля значение — `{{{сертификат}}}`. Свои значения лежат в iCloud рядом с модулем, файл `*.meta`. Экран: модуль → править параметры.

## `[Script]`

Строка задаёт тип, путь и движок. Пример формы из справочника: `имя = type=rule,script-path=rule.js`.

| `type` | Когда выполняется |
| --- | --- |
| `http-request` | Перед запросом, может его изменить |
| `http-response` | На ответе |
| `event` | На событии |
| `rule` | Как правило, на него ссылается `SCRIPT` |
| `dns` | Как резолвер |
| `cron` | По расписанию |

Движок: `jsc` для коротких частых скриптов (правила, DNS), `webview` для тяжёлых, `auto`. При `auto` у `http-request` и `http-response` справочник фиксирует выбор WebView и советует писать движок явно.

Скрипты по URL видны в редакторе файла, строка «скрипты URL»: галочка — скачан, крест — нет. Повторная загрузка одной строки файл не перекомпилирует.

## Модули

Модуль — тот же формат, что конфиг, обычно с частью разделов. Правила модуля выше правил файла. Модуль с правилами работает в глобальном режиме «конфигурация»; модуль без правил от режима не зависит. Модуль с `[MITM]` ожидает включённую расшифровку или модуль сертификата.

Порядок, включение и удаление пачкой — кнопка «···» над списком. Пропажа при включённом iCloud: в системе должны быть включены iCloud Drive и Shadowrocket, в «Файлах» папки `Shadowrocket/Modules` и `Shadowrocket/Script`, сами файлы модулей скачаны, а не только в виде значка облака.

На системах до iOS 15 лимит памяти сетевого расширения 15 МБ, дальше 50 МБ. Переполнение рвёт VPN. Справочник в этом случае включает «всегда включено». Если модуль молчит при живом сертификате, файл заново компилируют: так подтягиваются удалённые куски.

## Настройки приложения

Их нет в `*.conf`, кроме случаев, где скрытый ключ назван заменой тумблера.

### Подключение

| Пункт | Поведение |
| --- | --- |
| Всегда включено | Поднимать туннель после обрыва и перезагрузки. Система иногда после перезагрузки его не поднимает |
| По требованию | Список условий сверху вниз. Совпадение домена будит VPN. Совпадение DNS или имени Wi-Fi включает или выключает. Доменом выключить нельзя. Пустой список при включённом режиме держит соединение всегда. Вместе с «всегда включено» побеждает «всегда включено». Срабатывание решает система: имя, которое уже в кэше DNS, запрос не пошлёт |
| Разрыв во сне | Рвать туннель по сигналу сна. Погасший экран ещё не сон |
| Показывать разрыв | Уведомление о разрыве |

### Туннель

«Принудительный маршрут» ставит маршруты туннеля выше местных, по умолчанию выключен. «Включая все сети» забирает в туннель всё, кроме служб, без которых устройство не работает. Отдельные тумблеры добавляют местную сеть (AirPlay, AirDrop, CarPlay), APNs и сотовые службы (VoLTE, звонки по Wi-Fi, IMS, MMS, визуальная голосовая почта).

### Прокси

| Пункт | Поведение |
| --- | --- |
| Тип HTTP | Системный прокси. Программы, которые его не берут, уходят в TUN |
| Тип None | Весь трафик в TUN. То же, что `compatibility-mode = 3`. Часть программ перестаёт видеть «включённый прокси»; проверку флага VPN в системе это не обходит |
| Режим совместимости | Для камер HomeKit: хаб в той же сети при включённом прокси получает адрес VPN и не может вернуть RTSP. То же, что `compatibility-mode = 5` |
| Передний прокси | Сначала HTTP или SOCKS5, потом уже правила и узел |
| Общий доступ | Раздать свой прокси по LAN или раздаче: на втором устройстве ручной HTTP-прокси, адрес и порт с экрана общего доступа. Экран устройства-источника лучше не гасить. Расшифровка HTTPS на приёмнике требует того же доверенного сертификата; на экране общего доступа её можно выключить. У программ на приёмнике нужен доступ к местной сети. Telegram системный прокси часто не берёт, ему SOCKS5 прописывают внутри |
| Скрыть значок VPN | Настройки → исключить маршрут `0.0.0.0/31`. Справочник считает это опорой на ошибку системы и не советует: сеть может встать |
| Мягкая смена политики | Старые TCP-соединения доживают. Без тумблера смена политики их рвёт |

### UDP, STUN, Tailscale

Запрет STUN отрезает WebRTC от внешнего адреса. Ключи `stun-response-ip` и `stun-response-ipv6` этот тумблер игнорируют и подставляют свой адрес.

Tailscale с версии 2.2.89 (3314) — отдельный модуль, не узел.

| Пункт | Поведение |
| --- | --- |
| Включить | Возить tailnet. Смена настроек перезагружает туннель. Политика правил — `TAILSCALE` |
| Экономия батареи | После первой синхронизации в простое отпускает сеть и поднимает её по нужде. В простое состояние сети не обновляется |
| Ключ аутентификации | Ключ из консоли Tailscale, многоразовый или одноразовый |
| URL панели управления | По умолчанию `https://controlplane.tailscale.com` |
| Выходной узел | По умолчанию выключен: наружу через Tailscale трафик не гонится, только tailnet |
| Всегда DERP | Только релей DERP, прямой UDP выключен |
| Подсети Tailscale | Принимать объявленные подсети. Нужно, чтобы ходить не только в `100.*` |

Диапазон `100.64.0.0/10` внутри `tun-excluded-routes` мешает Tailscale: это его адреса.

### GeoIP

Встроенной базы хватает для `GEOIP` и `IP-ASN`. Замена: учётная запись MaxMind либо свой URL файла mmdb, отдельно для стран и для ASN. «Сбросить» возвращает встроенную базу. Справочник даёт такие адреса:

```
https://raw.githubusercontent.com/Loyalsoldier/geoip/release/Country.mmdb
https://github.com/Hackl0us/GeoIP2-CN/raw/release/Country.mmdb
https://github.com/Masaiki/GeoIP2-CN/raw/release/Country.mmdb
https://github.com/P3TERX/GeoLite.mmdb/raw/download/GeoLite2-ASN.mmdb
```

### Автообновление

Нужен фоновый режим приложения в системе. Убитый процесс фон не поднимает.

| Объект | Период | Что ещё |
| --- | --- | --- |
| Конфигурация | 1–7 суток | Качает файл по `update-url` и заодно наборы правил и скрипты. У местного файла без адреса обновляются только наборы. Напоминание — через уведомления |
| Модули | 1–7 суток | Удалённые модули |
| Подписки | 1–24 часа | Отдельный DoH для имени подписки, сортировка по ping, сохранять цепочку, слать заголовок `X-HWID`, спрашивать перед удалением узлов с таймаутом |
| GeoLite2 | сутки | Та же база, что в пункте выше |

Чтобы фон обновлял наборы и не затирал правки: закомментировать `update-url` или вынести правки во включённый файл, который важнее скачиваемого.

### Журналы и синхронизация

Журнал прокси (Данные → прокси): URL, политика, протокол, время. Пометка MITM — имя расшифровывалось. Из записи можно сразу добавить правило. Журнал DNS: имя, ответ, время, какой сервер ответил, флаг по адресу.

Автоудаление снимает журналы старше 7 суток. Ручное удаление при включённом туннеле оставляет самый новый файл.

iCloud синхронизирует узлы, конфиги, модули и скрипты. С версии 2.2.93 (3471) выгрузка и загрузка разделены. Узлы лежат в `shadowrocket.v2.model`. Сценарии и группы главного экрана в эту синхронизацию не входят.

Статистика показывает время сессии и трафик Wi-Fi и сотовой сети. «Архив» хранит цифры каждой сессии отдельно.

### Прочее по экранам

Разрешения: геолокация только ради имени Wi-Fi в сценариях, уведомления для скриптов, подписок и разрыва VPN, буфер обмена для автоимпорта ссылки. Без буфера на главном экране есть кнопка вставки.

Виджет: до шести узлов, показ ping и сортировка по нему. Цвета интерфейса задаются шестнадцатеричными кодами и ставятся ссылкой `shadowrocket://color?...`. Имена полей из справочника: `NavigationBarColor`, `NavigationBar2Color`, `NavigationBarTextColor`, `NavigationBar2TextColor`, `TabBarColor`, `TabBarBorderColor`, `TabBarSelectedColor`, `TabBarUnselectedColor`, `TableBackgroundColor`, `TableCellBackgroundColor`, `TableCellSelectedBackgroundColor`, `TableSeparatorColor`, `TextFieldTextColor`, `PlaceholderColor`, `TextLabelTextColor`, `DetailLabelTextColor`, `TextLabelDeleteColor`, `HeaderFooterTextColor`, `SearchFieldBackgroundColor`, `IndicatorColor`, `ButtonIconColor`, `ButtonNormalColor`, `ButtonNormal2Color`, `ButtonNormal3Color`, `ButtonHighlightedColor`, `ButtonHighlighted2Color`, `ButtonHighlighted3Color`, `ButtonDisabledColor`, `ButtonDisabled2Color`, `PingSuccessTextColor`, `PingTimeoutTextColor`, `DefaultDotColor`, `HUDBackgroundColor`. Часть полей система не даёт менять.

С версии 2.2.30 минимальная система — iOS 12. Сборка 2.2.29 и старше собиралась Xcode 13 и ставится на iOS ниже 12; последняя такая в справочнике — 2.2.28.

## URL-схемы

К запросу можно добавить `autoclose=true`: после действия приложение закроется. В фигурных скобках ниже — подставляемое значение, скобки в готовую ссылку не входят.

| Действие | Ссылка |
| --- | --- |

## Чего в открытых источниках нет

- Полного списка скрытых ключей. Группа сама пишет, что он может быть короче, чем умеет программа.
- Режимов UDP-релея внутри узла. Описан только тумблер пересылки.
- Отдельной спецификации строк `[Header Rewrite]`, `[Body Rewrite]` и `[Map Local]`: названы поля и типы, не грамматика строки.
- Описания `bypass-tun` и формы `hijack-dns = :53` в справочнике 2026 года.
- Поведения конкретной сборки. Перед опорой на ключ его стоит сверить с версией на устройстве.

Англоязычные сайты с заголовком вроде «official Shadowrocket manual» в выдаче повторяют короткие примеры и полного списка ключей не содержат. В этот файл они не вошли.
